# マコトカメラ 試作版 0.1.0

撮影した写真に「署名付きの記録」と「見えない透かし」を入れ、あとから編集の有無を判定するカメラアプリです。
Android 版と iPhone 版は同じ仕様で、どちらで撮った写真も、どちらでも判定できます。

## できること

- 撮影: ズーム、広角(対応機種)、明るさ、フラッシュ、内外カメラ切替
- 写真への表示: 日時(日本時間)、緯度経度、標高、アプリ名、AI編集不可ロゴ(「表示 切」で非表示)
- 表示を切っても必ず残る記録: 日時、位置、標高、機種名、OS、撮影設定、撮影ID(署名付き)
- Exif: 日時(+09:00)、GPS、標高、機種名、アプリ名
- 判定: 原本 / 撮影後に変更 / 記録の偽造 / このアプリの写真だが原本ではない / 確認不能
- 変更された場所を赤く表示(記録が残っている場合、または撮影した端末で判定する場合)

## ビルド方法

### Android(`android` フォルダ)

1. Android Studio(無料)を入れる
2. 「Open」で `android` フォルダを開く。初回は部品のダウンロードに数分かかる
3. スマホを USB でつなぎ、スマホ側で「開発者向けオプション → USB デバッグ」を入にする
4. 上部の ▶ を押す

対応: Android 10 以降。

### iPhone(`ios` フォルダ)

Mac と Xcode 16 以降が必要です。

1. `ios/MakotoCamera.xcodeproj` を開く
2. 左の一覧で一番上の MakotoCamera → TARGETS の MakotoCamera → Signing & Capabilities で、Team に自分の Apple ID を選ぶ
3. Bundle Identifier を自分用の文字列に変える(例: `jp.自分の名前.makotocamera`)
4. iPhone をつないで ▶ を押す

プロジェクトが開けない場合は、Xcode で「iOS App(SwiftUI)」を新規作成し、`ios/MakotoCamera` の `.swift` ファイルをすべて入れ替え、
Info の設定に `NSCameraUsageDescription`、`NSLocationWhenInUseUsageDescription`、`NSPhotoLibraryAddUsageDescription` を追加してください。

対応: iOS 16 以降。カメラはシミュレータでは動かないので実機が必要です。

## 確認済みのこと、未確認のこと

- 確認済み: 署名、透かし、判定の計算部分(Android 版と同じ Kotlin コード)を、サンプル写真 5 枚 × 2 サイズでテスト
  - そのまま → 原本
  - 1 バイト改変 → 変更あり
  - 記録の書き換え → 偽造
  - 部分的な塗りつぶし → 変更あり、場所を表示
  - 再圧縮、50% 縮小、30% 縮小 + 強い圧縮 → 透かしから撮影ID を復元(4000px の写真は全て成功。1200px を 360px まで縮小した場合のみ 2 件失敗)
- 未確認: Android の画面とカメラ部分、iPhone 版の全体は、この作業環境ではビルドできなかったため、実機での動作は未確認です。
  初回ビルドでエラーが出たら、エラー文をそのまま送ってください。

## 仕組み(共通仕様 v1)

1. 透かし: 画像を 64×64 のセルに分け、各セルに淡い波模様(輝度 ±3〜6)を足す。模様の向きで 64bit(撮影ID 48bit + 検査用 16bit)を繰り返し埋める。
   セルは画像サイズに比例するので、縮小や再圧縮の後でも読める。
2. 記録: JPEG の APP11 セグメントに「記録(JSON)+ 署名 + 公開鍵」を入れる。記録には画像本体の SHA-256 が入るので、画像が 1 バイトでも変わると一致しなくなる。
3. 署名鍵: 端末ごとに 1 つ。Android は Keystore(StrongBox 優先)、iPhone は Secure Enclave の中で作り、秘密鍵は取り出せない。
4. 控え: 撮影した端末の中に記録の控えを残す。記録が消された写真でも、透かしの撮影ID から照合できる。

コードの場所: `android/app/src/main/java/app/makoto/camera/core/MakotoCore.kt`、`ios/MakotoCamera/MakotoCore.swift`

## 試作版の限界(配布前に対応が必要)

- 他の端末の鍵が本物のアプリのものかは確認していません。偽の鍵で署名した写真も「原本」と出ます。
  対策: Android の Key Attestation、iPhone の App Attest と、鍵を登録するサーバー。
- 記録の控えは撮影した端末にしかありません。サーバーに預ければ、誰の端末でも照合できます。
- 時刻は端末の時計です。サーバー時刻を使えば偽装を防げます。
- 位置の偽装は、OS が「疑似位置」と報告した場合だけ記録されます。
- 画面に映した画像を撮影する手口は防げません。
- 切り抜きと回転の後は、透かしを読めません。
- 写真は sRGB の JPEG(画質 95)で保存します。HEIF や RAW には対応していません。
- Android の標高は、Android 14 以降で平均海面からの高さ、それより前は楕円体高(数十 m ずれることがある)です。
- 「マコトカメラ」の名前は商標とストアでの重複を未確認です。


## iPhone 版(`ios` フォルダ)

Android 版と同じ機能(比率、QR、かざして簡易確認、端末登録、元写真の検索、他のアプリから開いて判定)を入れています。
写真の形式は共通なので、Android で撮った写真を iPhone で、iPhone で撮った写真を Android で判定できます。

- `ios/` を変更して GitHub に入れると、Mac 環境で自動的にビルドの確認が走ります(Actions の「iOS build check」)。
  これはビルドできるかの確認だけで、iPhone に入れるファイルは作りません。
- iPhone に入れるには、Mac と Xcode が必要です(手順は上の「iPhone」を参照)。
- iPhone では、メールの添付やファイルアプリの写真を「共有」→「マコトカメラ」で判定できます。
  写真アプリや LINE の共有一覧には出ないことがあるので、その場合はアプリの「写真から」で選んでください。


## PC 版の判定(`pc/makoto-verify.html`)

確認する人のための、ブラウザで開く判定ページです。インストールは要りません。

- `pc/makoto-verify.html` をダウンロードして、Chrome や Edge で開きます(ダブルクリックで開けます)。
- 写真はブラウザの中だけで調べ、PC の外には送りません。
- 判定はスマホのアプリと同じです(原本、変更あり、偽造、透かしのみ、QR の複製)。
- 登録した端末は、そのブラウザの中だけに保存されます。
- スマホの中にある控えとの照合(元写真の検索)はできません。
- 写真の中の QR を読む部品だけはインターネットから読み込みます。つながっていなくても、QR の照合以外の判定はできます。
